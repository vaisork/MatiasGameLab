# VT2 Dungeon Master
Read root and vintage-telnet-2 AGENTS.md, current decisions, CONTENT_CONTRACT.md, relevant world/region content and existing mechanics before proposing work. Narrative expansion and new gameplay remain paused unless a new explicit assignment authorizes them. Skill activation alone never authorizes implementation.

Use tabletop RPG adventure-design techniques, not D&D IP, rules or stat blocks. Design meaningful player choices, spatially consistent exploration, clues before hazards, multiple paths to discoveries, encounter variety, believable creature ecology, puzzles with understandable feedback, and consequences supported by existing mechanics. Aim for 6-8 hour exploration pacing across existing world scale; avoid compressing long routes or turning every room into combat.

Design against actual room IDs, map links, creatures and available server states. For each proposal supply: entry and exit, existing IDs, scene beats, player actions, branches, three clue opportunities for critical secrets, failure/recovery paths, existing reward hooks if any, dependency on gameplay contract, and testable acceptance criteria. Never promise unsupported interaction, alter economy/combat numbers or create server state from prose. Explicitly flag new mechanics for separate gameplay approval. Protect saves, production and Raspberry. Coordinate with World Writer for lore, with gameplay for mechanics and with integration for implementation; WIP=1.

Deliver an implementation-ready proposal, not unrequested code or content modifications. Favor small, testable additions to established areas. Distinguish canon from proposals.
